# 月月游戏中心

Discord 小活动前端与 FastAPI 服务。现有 21 点已补齐窗口适配、断线恢复、多人轮次和月月陪玩；大厅支持德州扑克、炸金花、斗地主、四人麻将。

## 月月大模型陪玩

服务端 `.env` 可配置 `GAME_LLM_ENABLED=true`、`GAME_LLM_BASE_URL`、
`GAME_LLM_API_KEY`、`GAME_LLM_MODEL`。默认模型名为“打牌LLM”；接口兼容
OpenAI Chat Completions。密钥仅在服务端使用，不进入前端或牌局响应。
`GAME_LLM_TIMEOUT_SECONDS` 默认60秒，支持2～300秒（包含排队与请求时间）；与房主设置的真人操作时长独立。`GAME_LLM_MAX_CONCURRENCY` 默认4。
修改配置后在牌局结清时重启游戏服务生效；缺少配置时继续使用原算法。

覆盖德州、炸金花、斗地主、两种麻将及多人21点的月月和陪玩座位。
模型只接收自己可见的手牌与公开信息，21点荷官保持固定规则。
模型返回先经过字段校验和规则引擎副本验证；网络错误、超时、格式错误或非法动作
均回退到本地算法。网络请求异步进行，不占用房间锁；重复轮询只产生一个请求，
旧回合的迟到结果丢弃。

对话按房间、局次和陪玩座位分别保存，互相不共享私有手牌。
本局公开行动记录持续保留用于记牌，近期对话按大小裁剪，避免越打越慢；
结束、离房销毁或下一局时清理旧上下文。会话保存在服务进程内存中，不跨服务重启。
参考项目 [tian11111/doudizhu](https://github.com/tian11111/doudizhu) 的模型建议和规则校验思路，未引入其代码。

## 灵石规则

所有游戏使用同一 `user_coins` 账户余额，不发放免费的局内积分。

- 四种桌游通过场次选择规则，无需填写带入金额：初级场底分 **1**、准入 **100**、单局最多输 **100** 灵石；中级场 **5 / 1000 / 500**；高级场 **20 / 5000 / 2000**。准入金额只检查余额，不收取门票。
- 自定义房间由房主设置底分与单局亏损上限；上限至少为 100 且不少于底分的 10 倍，没有固定玩法上限，受真人余额及 JavaScript 安全整数约束。房主更改设置后，真人需要重新准备。
- 开局一次冻结本局亏损上限，结束返还剩余部分及收益。任一玩家余额不足准入要求，整桌开局回滚；不会自动追加损失上限之外的账户灵石。
- 德州为 2–8 人，小盲为房间底分、大盲为其两倍，支持全下及边池。金花为 2–5 人，底注等于房间底分。
- 斗地主为 3 人，房间底分 × 叫分 × 炸弹／春天倍数；麻将为 4 人，自摸每家付一倍底分，放铳者付三倍。理论赔付超过单局亏损上限时，按实际可付底池比例分配，整数尾差保持守恒。
- 单挑也结算账户灵石。月月和补位机器人使用同额模拟筹码，只为真人写账户及流水；机器人不读取真人暗牌来决策。
- 21 点沿用逐局下注，默认及小额快捷下注为 100，也保留原有自定义小额下注。普通获胜返还 2 倍、天然 Blackjack 返还 2.5 倍、平局退本金。单人双倍下注需要用户主动点击并追加同额灵石，多人不支持双倍下注。

具体牌型、先后顺序与玩法差异见页面内“玩法规则”。基础麻将保留 136 张规则；另可切换独立的 108 张四川血战，支持定缺、一炮多响、抢补杠、胡后续局、杠分及流局查账。血战三家胡或流局才统一结算账户灵石，途中显示待结算理论分。六番 32 倍封顶，不含换三张、天胡地胡、呼叫转移和过胡限制。详细房间约定见玩法规则；斗地主不包含癞子、抢地主等地方变体。

## 运行与部署

需要 Python 3.10+ 及兼容 Vite 7 的 Node.js。以下命令从仓库根目录在 PowerShell 执行，依赖安装到项目虚拟环境：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
Push-Location src/chat/features/games/blackjack-web
npm ci
npm run build
Pop-Location
.venv/Scripts/python.exe -m uvicorn src.chat.features.games.blackjack-web.app:app --host 127.0.0.1 --port 8484 --workers 1
```

构建后 FastAPI 同时提供 API 和 `dist` 静态资源。开发可另开 `npm run dev`，Vite 默认把 `/api` 转发至 8484；可用 `VITE_API_PROXY_TARGET` 指定开发后端。

**游戏 Web 服务必须单进程、单实例运行。** 房间及回合锁仍存内存，不能使用多个 Uvicorn worker 或多个副本连接同一钱包。开发 `--reload` 会重建房间，不适用于正在进行的真实牌局。现有机器人入口仍由主程序扫描 `features/*/cogs` 加载，但该扫描不会代替启动 Web 服务。

生产环境在仓库根 `.env` 配置 `DISCORD_CLIENT_ID`（兼容 `VITE_DISCORD_CLIENT_ID`）、`DISCORD_CLIENT_SECRET`。按现有 Discord 活动配置，将公开 HTTPS 地址映射至此服务，Bot 与 Web 服务使用同一持久化 `data/chat.db`。招募界面使用 Discord SDK 原生分享，不需要额外的 Bot Token；旧版服务端招募接口仍需 `DISCORD_TOKEN`（兼容 `BOT_TOKEN`）。本次未修改或发布 Discord 应用配置。

无 Bearer Token 时，只有未配置 Discord Client ID 且未设置开发鉴权开关的回环请求允许开发身份。生产部署必须正确配置 Client ID，并显式设置 `BLACKJACK_ALLOW_DEV_AUTH=false`，此时回环及代理请求也必须认证。`BLACKJACK_ALLOW_DEV_AUTH=true` 仅供隔离测试，不能用于公开服务。开发页面可用 `?dev_user_id=123456789012345678&dev_username=PlayerA` 区分测试用户；不会因进入页面自动赠送灵石。

## 联机与资金恢复

- 四种桌游支持刷新重连、成员权限、暗牌隔离、操作版本校验、60 秒超时托管；真人离桌后由 AI 完成本局，输赢仍正常结算。
- 单人房间创建时配齐陪玩，此后也允许房主逐个移除（包括月月），不会自动补回。等待及已结算时可选择添加人数，只追加指定数量且保留已有座位。进行中的牌局不能调整座位；人数不足时不能开局。
- 后台任务独立推进 AI 和超时，即使无人打开页面也会完成桌游。重连不会重新延长已有截止时间。
- 新桌游 `table_game_escrow` 账本将余额、流水和轮次状态放在同一 SQLite 事务中；重复结算不重复入账。启动时自动退还上次未结算的托管款，已结算轮次不会重复退款。
- 共享灵石服务的单笔加减款及流水也已原子提交，条件扣款可防止黑杰克下注与桌游同时消费造成透支。
- 黑杰克单人支持恢复已保存牌局，重复开局返回 409；多人逐玩家确认派彩并可在失败后重试。
- **现有黑杰克多人房间与派彩确认仍为内存态，不具备新桌游账本的完整重启恢复保证。** 服务异常终止时仍需核对其下注／派彩流水。单人旧存档退款路径同样未升级为新桌游事务账本。上线重启应等待黑杰克牌局结束。

## 牌局动画与结果

- 21 点单人和多人逐张发牌、补牌及荷官翻牌；本人的大号点数独立展示，21 点与爆牌分别突出。实时跨过 21 点播放 16 帧爆裂动画，对手和荷官同样支持。
- 四种桌游按座位飞入牌背，新增手牌独立入场；弃牌、排序及同状态轮询不重新发牌。麻将区分本人胡牌、他人胡牌及流局。
- 胜负用独立结果绶带与有限粒子呈现，动画结束保留文字；桌游到账前显示结算处理中，到账后仅展示服务端实际结算净额。斗地主农民同队胜利按队伍判断。
- 恢复中的旧牌局静态显示，轮询不重复播放；新局和退出清理定时器。系统设置减少动态效果时直接显示稳定结果。

## 素材

大厅和五款牌桌参考国潮茶楼风格：暖色室内、蓝紫金边牌桌、橙金与青蓝胶囊按钮。五款游戏入口采用新生成的透明 WebP 插画，三级场次、模式和管理入口保留 SVG；牌桌与云纹为本地绘制的 SVG。入口和按钮保留键盘焦点与触控区域，房间设置及陪玩管理使用原生对话框。

茶楼背景、五游戏插画及 16 帧爆牌序列通过用户指定的 `chatgpt-gpt-image-2` 生成后处理，放在 `public/ui/guochao/`。来源和处理记录见该目录的 `ATTRIBUTION.md`，实际生成提示词见 `PROMPTS.md`。生成接口仅用于离线制作，游戏运行不依赖该服务，也不包含其密钥。

扑克与月月角色沿用项目现有资源。麻将牌复用 Perth Mahjong Society 的 SVG 素材，采用 CC BY-SA 4.0，归属与许可见 `public/mahjong/ATTRIBUTION.md`、`LICENSE.txt`，页面规则中也提供来源链接。

仍在使用的牌背等资源来自 CragonGame/CasinosClient 的 MIT 素材，筹码来自 Screaming Brain Studios 的 CC0 素材；此前牌桌和房间素材也保留在资源目录，当前主视觉由国潮素材替换。来源、修改与许可见 `public/table-assets/ATTRIBUTION.md`。用户提供的 mj-yl 项目仅用于理解四向布局，不引入其代码和贴图，麻将提供原有 136 张基础麻将与独立 108 张四川血战。原斜视素材保留，实际游戏改用 faces/ 目录中去掉牌壳、等比放大的正面花色，修改版继续采用 CC BY-SA 4.0。
