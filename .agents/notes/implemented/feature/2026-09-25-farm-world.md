# Agent Note: 月月大厅与灵圃统一洞府场景和灵兽经营

Status: implemented

## Problem

大厅和农场的画风割裂，卡片与侧栏遮住场景，浇水缺少动作反馈。用户指定“云梦洞府”参考：2.5D山间悬空庭院，草地、屋舍、竹林、灵泉和瀑布占主体；按钮、灵兽、道具需要真实生成图片。

## Decision

大厅和灵圃共用青玉、暖金、草木及云雾画风。场景与热点统一使用1536×1024坐标和cover映射，保留GameViewport的自动旋转与Discord安全区。大厅玩法为石桌热点；农场田地为独立透明土块，点选才展开动作，经营功能放在可关闭抽屉。

`public/ui/farm-v2`包含45项WebP素材：两个背景、一块土田、三只灵兽、六件道具、十二个按钮图标、八个玩法摆件、六种边框、六套八帧动作及一套成长阶段图。合计约3.1MB，manifest记录来源文件、尺寸、透明通道、逐帧差异和SHA-256。图片使用用户提供接口的chatgpt-gpt-image-2.5-sunburst生成；凭据不进入代码或资产。

浇水、成长、采收和三只灵兽待机采用生成图集切成2048×256横条。统一锚点保留真实动作位移；灵狐一张朝向翻转的帧替换为相邻同向帧。每块田的反馈互不截断，后台暂停，减少动态时显示静帧。成熟植株复用现有八种生成素材。

灵兽最多装备一只，购入附24小时守护，口粮每次增加24小时、剩余最多72小时。三宠防偷概率为25%/40%/15%，仙鹤在守护期增加5%基础生长期的浇水减时。灵露每茬额外减10%，护田符每茬保护1小时。服务端控制价格、拥有关系和次数。

沿用事务和JSON状态，无新表迁移。被抓也消耗当日偷取次数，同人同茬仅一次尝试；幂等重放不重新抽概率。双方有事件记录，访客看不到私有库存与购买记录。旧请求指纹字段保持兼容。

本轮附带的指定账户核查保留本地逐局三方证据。实时余额不满足用户给定条件，因此没有扣款、撤销红包或改排行榜。累计盈利不作为当前可用余额。

## Validation

- 后端96项测试通过，覆盖事务回滚、并发与幂等、概率边界、过期、同茬限制、道具上限、权限和访客隐私。
- 前端51项集成测试通过，含28项农场、23项大厅及月月互动；检查实际图集加载、帧移动、十二田点击、入口与声音、横竖屏及Discord安全区。
- 实际截图复核1440×900、1024×600、844×390、390×844；不额外以320×568作为验收要求。
- 生产构建通过。发布沿用暂停新局、自然排空、账本复读、SQLite只读备份、限定代码与静态白名单流程，只重启bj-web。
- 静态发布函数在临时目录实际验证新增目录、原子入口更新、旧文件保留和精确回滚。

## Alternatives considered

- 只调饱和度或继续八张大卡片：不符合用户指定完整洞府场景。
- 固定30%常驻商店侧栏：用户已否决，占用过多场景面积。
- 用CSS缩放代替所有生成帧：无法表现水流、采收与宠物具体动作。
- 修改数据库结构或重写农场钱包：现有JSON状态与事务可兼容扩展，额外迁移无必要。
- 仅按排行榜改余额或删除牌局结果：会破坏余额与统计口径，也超出本次附条件授权。

## Consequences

界面可直接在场景中游玩，素材与经营功能一致。代价是新增约3.1MB资源与坐标适配；透明独立素材、WebP和暂停机制控制传输与动画开销。参考场景是静态绘景，交互田地、人物、按钮和动作独立叠放，不宣称完整3D场景。
