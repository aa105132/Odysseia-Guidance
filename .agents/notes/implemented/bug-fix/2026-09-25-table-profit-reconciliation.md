# Agent Note: 桌游异常盈利追回与统计冲正

Status: implemented

## Problem

高额自定义房间的历史异常盈利计入钱包、原日期排行榜和个人极值。用户明确授权扣除已核实异常所得；部分资金存放于本人未领取的红包。删除原结果会被旧托管回补，覆写返还则破坏结算幂等。

## Decision

追加 table_game_adjustments，以 round_key/user_id 唯一标记逐局盈利撤销。原 table_game_results、table_game_escrow、table_round_details 保持不变；统一结果查询叠加调整，按原日期和玩法影响当日榜、总榜、胜率、最高单局盈利，不增加场次。个人详情保留原始投入与返还，显示原盈利、冲正额、有效盈利和原因。

scripts/reconcile_table_profits.py 是离线管理员工具，不暴露 HTTP 接口。默认完整事务演练后回滚，明确 --apply 才提交。私有清单指定用户、逐局证据及红包白名单，复核结算三表、详情哈希、未冲正且没有本人未结托管。

只撤销指定用户完整未领取的红包，将全部余款退回本人，再精确扣回清单正盈利，不扣本金或其他账户。已到期全额退款时不再退款；领取记录、归属改变、证据不符或资金不足均拒绝整笔操作。

退款、扣款流水、逐局调整与操作回执在同一 BEGIN IMMEDIATE 事务提交。操作号和清单 SHA-256 校验幂等，重复返回原回执，不同清单及不同操作号重复处理同局均拒绝。原结算重试不能重新发放已撤销收益。

## Validation

- 68项合成 SQLite 测试通过：演练无残留、原始三表和他人账户不变、原日期和分游戏统计、历史详情、失败全回滚、证据冲突、过期退款、重复执行与并发重试。
- 个人面板、排行榜和历史详情11项浏览器测试通过，生产构建通过。
- 生产使用私有逐局清单与回执，不提交账户明细或凭据。先备份并部署统计读取逻辑，再执行原子追回。

## Alternatives considered

- 仅扣可用余额：遗漏本人红包托管。
- 扣红包领取者：超出指定账户范围，且本次不需要。
- 删除或覆写原始结果和托管：损坏审计及重试语义。
- 新增负利润牌局：虚增场次、扭曲最大亏损和扣款当天排行榜。

## Consequences

追回准确异常利润，正常收益和他人账户不变；原场次保留，撤销盈利的局按有效盈利0参与统计。新增两张小型审计表和一次主键关联。工具只支持整局正盈利撤销，部分冲正与反冲不在本轮范围。
