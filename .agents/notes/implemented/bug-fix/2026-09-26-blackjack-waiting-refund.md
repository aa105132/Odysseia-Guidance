# Agent Note: 多人21点等待下注离线超时退款

Status: implemented

## Problem

多人21点在等待阶段立即扣除下注，显式离房会退款，但关页面不发离房请求，服务端只有进行中回合超时。等待下注可能无限保留。房间 `updated_at` 不是每个玩家的在线时间，其他人的操作会更新它；后台多人检查还依赖 LLM runner 存在。

## Decision

- 使用独立的逐玩家单调时钟在线时间；本人认证轮询、重连和操作续期，内部后台读取及他人请求不续期。
- 尚未开局的真人连续300秒没有心跳后，全额退回当前下注并离房，沿用房主转移和最后真人离房关闭逻辑。已开局不走该退款。
- 每次等待下注使用独立退款键；显式离房与超时退款共用持久化幂等退款接口。余额、流水及退款键同一 SQLite 事务提交，不记为牌局输赢。
- 退款意图在内存先标记，失败或取消后继续重试；在完成前禁止该玩家改下注及房间开局。用房间锁串行化退款、下注、开局、重连。
- 多人后台推进独立于模型开关。开局前检查超时成员，避免在两个后台 tick 之间将到期押注投入游戏。

## Alternatives considered

- 页面卸载时发送 leave/beacon：网络中断时不可靠，而且会把已开局的关闭页面误变成主动弃局。
- 按房间更新时间退款：在线房主会替离线成员续期，反之也可能误退仍在线的等待者。
- 所有退出立即退本金：改变已开局输赢规则，可逃避输局，不采用。
- 直接重复调用加币接口：提交成功但响应失败后可能重复退款，不采用。
- 重构全部多人21点下注为持久化托管：涉及开局消费及中断恢复契约，超过本次离线退款修复范围。现有等待房间仅驻内存，进程在超时处理前终止的恢复问题不由本修复解决；也不根据旧流水猜测补退历史资金。

## Consequences

未开局押注不再因关页面无限等待，退款失败可以重试而不会多退；正常在线等待不会因房间总年龄被取消。多人21点在模型关闭时也继续后台推进和派彩，未改已开局的主动弃局判负规则。

代价是每个付费等待席位维护内存在线时间、退款键与冻结标记，数据库长期保留一条每次实际退款的幂等记录。浏览器或网络连续暂停超过5分钟也视为离线；这是可恢复的等待取消而非惩罚。重连和超时处理按同一房间锁先后顺序决定；退款一旦开始，重连不撤销退款。

老版本内存房间不能靠本地修复追溯恢复，上线前仍需独立核账与安全发布。等待下注跨进程中断的持久化恢复仍属现有限制；本次不解析旧流水自动补退，也不以重启清理线上押注。
